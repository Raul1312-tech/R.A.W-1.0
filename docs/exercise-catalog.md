# Persistent exercise catalog

The Supabase table `public.exercise_catalog` stores 37 versioned exercise records: stable ID, name, aliases, purpose, execution steps, common mistake, starting advice, and illustration reference (asset path and tile coordinates). It contains no athlete data. RLS permits read-only access to published content for anon/authenticated; those roles have no INSERT, UPDATE or DELETE privileges. Existing journals and ownership policies are untouched.

Images are durable, versioned assets on the application CDN, referenced by each database record. They are NOT generated on routine creation or requested from an image service at runtime. All image generation happened once during development with the built-in image tool. Current assets: `public/training/boxing-exercises-v2.png`, `public/training/catalog-a.png`, `public/training/catalog-b.png`, `public/training/catalog-c.png`.

`/api/exercises` reads published records with the public project key, validates their shape and merges them over the bundled catalog snapshot. Invalid or unavailable database rows fall back to the versioned snapshot. Browser requests are shared while the component is mounted. The public response can be cached for five minutes; no session cookies or private journal payloads enter this endpoint.

New routines store `catalogId`. Legacy exercises resolve by exact normalized name/alias, so their instructions and images appear without rewriting recorded prescriptions or workout history. The library also lets users search and consult any exercise outside a routine.

Maintenance: add/review an entry in `app/exercise-catalog.ts`, create its illustration once, and add an upsert in a new CLI-created migration. Keep the ID stable and increment `version` for edits. `scripts/build-exercise-catalog-seed.mjs` builds the initial migration from the validated snapshot; do not reapply the initial CREATE TABLE migration to an existing database. Tests cover every exercise emitted for both sports, equipment variants, levels and phases, plus legacy names and asset existence.
